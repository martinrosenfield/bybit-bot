# Bybit demo-бот: запуск на Mac (DRY_RUN → реальные демо-ордера)

Дата сборки: 13.10.2026 (обновлено 14.10 — параметры риска). Бот работает
ТОЛЬКО с демо-окружением Bybit (`demo=True` жёстко зашит в коде — живой API
недостижим даже при живых ключах). Правила допуска из STATUS_SYNC.md сохранены:
реальный счёт — только после отдельного подтверждения; этот комплект к нему не
подключается в принципе.

## Состав

- `bybit_bot.py` — сам бот (EMA20/50, M15, ATR14, BTCUSDT+ETHUSDT, плечо ×3,
  риск 0,25% equity на сделку ВКЛЮЧАЯ комиссии, дневной лимит −1%, макс. 3 входа/день на символ)
- `config.json` — параметры (в т.ч. `"dry_run": false`, `taker_fee_rate`)
- `bybit_report.py` — дневной отчёт (читается в любой момент, read-only)
- `MIGRATION_VPS.md` — план переноса бота на VPS (Нидерланды), когда решим

## 0. Получение кода (git clone — предпочтительно)

```bash
cd ~/Documents/ChatGPT/Трейдинг
git clone https://github.com/martinrosenfield/bybit-bot.git

```

Проверка целостности после клона/обновления:

```bash

git log --oneline -3  # сверить с последними коммитами в репозитории
```

## 1. Обновление бота (после изменений в репозитории)

Бот при этом останавливается на ~1 минуту. Ключи в RAM сотрутся — вводим заново
(шаг 2), затем запускаем (шаг 4).

```bash
cd ~/Documents/ChatGPT/Трейдинг/bybit-bot
pkill -f bybit_bot.py && sleep 2
git pull
python3 -c "import ast; ast.parse(open('bybit_bot.py').read()); print('syntax OK')"
md5 bybit_bot.py config.json   # записать новые значения в TRADING_SYNC.md
```

## 2. Установка и ключи

```bash
pip3 install "pybit>=5.8"      # demo=True появился в 5.8.0
export BYBIT_API_KEY="..."
export BYBIT_API_SECRET="..."
```

Ключ — тот же системный HMAC с демо Bybit (Read/Write, деривативы, IP не привязан).
VPN: сервер Нидерланды (Швеция попадала под 403).

## 3. Обязательный прогон dry-run перед живыми демо-ордерами

В `config.json` временно выставить `"dry_run": true`, затем:

```bash
python3 bybit_bot.py
```

В логе должно быть: `PREFLIGHT` с equity ~185k, по каждому символу
`last/ATR/stop/tp` и `leverage set to x3`. Дай боту проработать хотя бы 1–2
новые свечи M15 и убедись, что нет ERROR. Всё чисто — гасим (Ctrl+C).

## 4. Переход к реальным демо-ордерам

В `config.json` вернуть `"dry_run": false`. Двойной стартовый барьер:

```bash
CONFIRM_LIVE=YES nohup python3 bybit_bot.py > bot.out 2>&1 &
```

Без `CONFIRM_LIVE=YES` бот с `dry_run=false` откажется стартовать — это и есть
твоё явное подтверждение из правил допуска.

## 5. Мониторинг

```bash
tail -f logs/bot.log                    # живой лог
python3 bybit_report.py                 # отчёт за сегодня (UTC)
python3 bybit_report.py 2026-10-13      # отчёт за дату
```

Отчёт показывает: equity и смену за день, закрытый PnL по API, сигналы/входы
(с пометкой DRY/LIVE), открытые позиции, срабатывания дневного стопа, ошибки.

События дублируются в `logs/events_YYYY-MM-DD.jsonl` — при следующей передаче
контекста в Kimi пришли этот файл(ы), и я смогу разобрать торговлю построчно.

## Параметры риска (калибровка под крипту, обновлено 14.10)

- Стоп = 1,5 × ATR14(M15) конкретного инструмента; тейк = 3,0 × ATR
  (валовый R:R 1:2; после комиссий тейкера ~1,2:1; безубыточный WinRate ~45%)
- Объём: риск 0,25% equity ÷ (стоп-расстояние + комиссии тейкера туда-обратно);
  не более 50% equity в нотионале (с плечом ×3 это ~16,7% equity в марже);
  минимальный нотионал $5, округление вниз по qtyStep биржи
- Комиссия тейкера `taker_fee_rate` в config.json (0,00055); при смене тарифа
  Bybit обновить, иначе расчёт риска поплывёт
- В логе теперь печатается `planned_risk` в USDT и % equity на каждый вход —
  сверять с лимитом 0,25%
- Дневной стоп: equity(начало дня UTC) −1% → новые входы запрещены до завтра;
  стопы по открытой позиции при этом остаются висящими на бирже
